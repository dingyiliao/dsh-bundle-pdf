# 2026-10-16 阅读交互优化基准

本目录保存优化前、分项试跑与优化后的原始记录。测量对象是 **原生 Reader 组件和独立 Host 组件**，不是完整 DSH Desktop；合成语料与无头浏览器结果不应被解读为真实文档、整机 CPU 或发布版本的加速承诺。

## 方法和原始数据

- 环境：macOS arm64、Apple M5 Pro、Node 26.7.0、Chrome 155.0.8059.40、PDFium 156.0.8076.0；浏览器视口 1200×900，DPR 2。
- Reader 使用 `smoke`、每场景 5 次、共 55 次；三个固定语料为 `paper-12`、`text-1000`、`annotations-1000`。改前和改后均为 **55/55 成功**，协议 SHA-256 均为 `3d41f3b8183f11462aaa600c66595a99a5d18a59110d288abca9cf7cc736f06e`。`bench:compare` 验证了环境、语料、缓存状态、迭代号和协议一致。
- [优化前 Reader](reader-before.jsonl)、[搜索与批注优化后、512px tile 试跑](reader-search-annotation-512.jsonl)、[1024px tile 候选试跑](reader-tile1024-trial.jsonl)、[最终 Reader、768px tile](reader-after-768.jsonl)、[完整指标对照](reader-comparison.md)。分项与候选试跑各为 55/55 成功，仅供权衡方案；最终结论以前后配对数据为准。
- [最终 Host](host-after.jsonl) 为 60/60 成功；本轮没有与它同协议的改前 Host 记录，故只报告绝对值，不计算 Host 加速比例。记录中的源码树标记为 dirty；基准结束后才加入本归档文档。

前后对照使用 p50（括号内为 nearest-rank p95）。每组只有 5 个样本，p95 实际是最大观测值，不是可信的尾延迟估计。下列“下降”按 `(旧 p50 - 新 p50) / 旧 p50` 计算；`searchCompleteMs` 尚未列入比较器的自动降幅名单，搜索百分比由原始 p50 手算。

| Reader 场景 | 指标 | 优化前 p50（p95） | 优化后 p50（p95） | p50 变化 |
| --- | --- | ---: | ---: | ---: |
| 12 页首屏 | 达到目标画质 | 159.1（198.9）ms | 136.2（188.0）ms | 下降 14.4% |
| 12 页缩放 4 倍 | 达到目标画质 | 266.9（267.5）ms | 250.2（250.3）ms | 下降 6.3% |
| 1000 批注首屏 | 达到目标画质 | 454.4（467.7）ms | 305.4（316.3）ms | 下降 32.8% |
| 1000 批注缩放 4 倍 | 达到目标画质 | 433.5（450.0）ms | 332.0（333.4）ms | 下降 23.4% |
| 1000 页首次无命中搜索 | 搜索完成 | 4183.4（4199.5）ms | 2499.9（2500.6）ms | 下降 40.2% |
| 1000 页同词重复搜索 | 搜索完成 | 2100.0（2100.4）ms | 33.3（33.4）ms | 下降 98.4% |

1000 批注首屏的 DOM 节点数从 11,069 降至 4,053（约 −63.4%）；同语料 4 倍缩放从 9,221 降至 2,195（约 −76.2%）。普通 12 页缩放的 RPC 请求数从 90 降至 50；这些计数包括场景的准备阶段，不能直接换算成 CPU 降幅。滚动时，`rafIntervalP95Ms` 的各次运行 p50 分别从 20.5 降至 18.6 ms（12 页）、19.1 降至 17.4 ms（千页）、22.7 降至 19.7 ms（千批注）；这是 rAF 回调间隔，**不是**实际 FPS。

权衡和未改善项：768px tile 使普通文档滚动时的已附着 canvas 像素字节估计从 18,714,976 增至 22,370,656（+19.5%）；千批注 4 倍缩放从 42,414,432 增至 47,657,312（+12.4%）。这些不是进程或 GPU 内存峰值。`text-1000` 滚动恢复清晰的 p50 从 32.6 变为 33.2 ms（+1.8%），12 页首个可用画面的 p95 从 165.7 变为 171.3 ms；小样本不能判定是否真实回退。1024px 候选的千批注缩放画布估计比 512px 高约 48%，因此未采用。Reader 的 `browserTotalRssMiB` 未采集，Long Tasks 为零也不能证明 CPU 占用为零。

Host 改后绝对值参考：千页打开检查 p50 壁钟 60.476 ms、CPU 122.204 ms；千页保存物化 p50 壁钟 61.666 ms、CPU 81.683 ms。CPU 时间可跨多个线程累加而超过壁钟。没有 Host 前测，不能据此声明 Host CPU 已下降。

验证：`npm run check`（214/214 Node 测试）、`npm run test:web`（14/14 浏览器测试）、Reader 55/55、Host 60/60，且最终 Reader 对照成功。功能测试覆盖搜索取消、长批注列表键盘/焦点/摘录与动态高度、缩放菜单和解释操作的点击区域。仍需在完整 DSH Desktop 与代表性真实 PDF 上测进程级 CPU/RSS、交互延迟和画质；本轮没有这类可配对的改前/改后数据。
