# 文档维护约定

本文列出项目文档的受众、权威来源与同步边界。版本、兼容范围和产品语义只在一个位置定义，其他文档引用而不复制完整契约。

| 文档 | 受众 | 权威语言 | 更新触发条件 |
| --- | --- | --- | --- |
| `README.md` / `README.zh.md` | 安装与使用者 | 英文；中文同步翻译 | 用户可见能力、限制、安装方式或安全后果变化 |
| `spec.md` | 产品与实现人员 | 中文 | 产品范围、交互或验收语义变化 |
| `docs/architecture.md` | 实现与维护人员 | 中文 | 模块职责、数据所有权或运行时边界变化 |
| `docs/working-copy-model.md` | Working Copy 维护人员 | 英文 | 基线、操作集、内容上下文或生命周期契约变化 |
| `docs/agent-tools.md` | 工具实现与使用者 | 中文 | 模型工具输入、输出、授权或失败语义变化 |
| `docs/releasing.md` | 发布维护人员 | 英文 | 构建、验证、打包或发布流程变化 |
| `CHANGELOG.md` | 升级用户与发布维护人员 | 英文 | 每项用户可观察变化；发布时冻结版本段 |

## 单一事实源

- 版本号：`package.json`。
- DSH 兼容范围：`package.json` 的 `engines.dsh`。
- 产品语义：`spec.md`。
- Working Copy 实现契约：`docs/working-copy-model.md`。
- 发布摘要：`CHANGELOG.md`，只记录用户影响和迁移动作，并链接权威契约。

## 同步规则

- 两份 README 必须在同一变更中保持相同标题顺序和功能项。
- 签名、加密、保存审批或数据生命周期变化必须同时检查 README、`spec.md`、Working Copy 契约和 CHANGELOG。
- 工程文档不强制逐篇双语；非权威翻译若落后，必须显式标注，不能无声漂移。
- 历史计划和基准必须在标题附近标明历史状态，不能冒充当前契约。
